## 실제 처리

1. **원문 보존:** 학생이 전송한 문장과 음성 인식 원문을 분리해 저장합니다. AI가 확장한 이미지 프롬프트를 학생의 언어 능력으로 분석하지 않습니다.
2. **Stanza 한국어 GSD:** `tokenize,pos,lemma,depparse`를 CPU로 실행합니다. 기본형·품사·수식·의존 관계, 내용어·다양도·키워드를 계산합니다. 한 글자인 ‘꽃’, ‘집’, ‘빛’도 내용어 후보로 남깁니다.
3. **문맥 의미 분석:** 같은 활동의 이전 발화 최대 4개와 현재 원문·구문 구조를 OpenRouter의 `openai/gpt-4.1`에 전달합니다. 학년·반·번호·이름은 분석 입력에 별도로 포함하지 않습니다.
4. **근거 검증:** Zod 스키마로 점수 범위·기준 ID를 검사하고, 모든 근거 인용이 현재 원문 안에 실제로 있는지 서버에서 확인합니다. 앞선 문장의 세부 표현을 현재 발화의 점수에 더하지 않도록 지시합니다.
5. **교사 검토:** 반어 가능/판단 유보, 이중 부정, 부정 범위 불명확 결과는 교사 확인 대상으로 표시합니다. 교사가 검토 메모를 남길 수 있습니다.

## 반어·이중 부정의 한계

Stanza 자체는 한국어 반어 판별기가 아닙니다. ‘참 잘했네’처럼 억양과 상황이 없으면 뜻을 단정할 수 없는 표현은 **판단 유보**가 타당합니다. 부정 표지 두 개를 단순히 세어 긍정으로 바꾸지 않습니다. ‘예쁘지 않은 것은 아니다’의 완곡한 긍정, ‘안 갈 수 없다’의 의무, ‘안 예쁜 꽃은 싫어’의 포함절과 주절을 구별하도록 의미 분석을 구성했습니다.

이 처리는 정확성을 보장하는 규칙이나 학습 능력 진단 도구가 아닙니다. 숫자형 ‘신뢰도’를 임의의 확률처럼 표시하지 않습니다. 비교 가능한 현재 평가 기준의 분석 표본 수와 근거를 함께 보여 주며, 기준 변경 전 기록은 평균에서 제외합니다. 어휘 다양도와 키워드 빈도도 구체성 점수와 분리합니다.

## 이번 검증 범위

- 실제 Stanza 모델로 예시 문장 8개의 품사·기본형·지배어·관계를 반환하는 것을 확인했습니다. 결과는 `output/nlp-verification.json`입니다.
- 초기 로컬 실행 평균은 약 45ms였습니다. CPU·모델 준비 상태에 따른 결과이며 운영 Container의 지연을 보장하지 않습니다.
- 예시에는 수량·감각 표현, 단일 부정·이중 부정, 문맥 없는 ‘참 잘했네’가 포함됩니다. 구조를 반환했다는 사실은 반어 정답률을 검증했다는 뜻이 아닙니다.
- 실제 키 설정 후 OpenRouter와 Stanza를 연결하여 합성 문장 7개의 스키마·원문 근거·기대 분류를 확인했습니다. 문맥 없는 반어는 판단 유보, 문맥 있는 반어는 반어 가능, 완곡한 긍정·의무는 이중 부정 및 교사 검토 대상으로 반환했습니다. 결과는 `output/live-language-check.json`입니다. 작은 수작업 예시이므로 정확도 수치나 도구 간 우열을 입증하지는 않습니다. 수업 전 실제 교과 발화 표본에 대해 교사 라벨과 일치도를 대조해야 합니다.

## 설치 부담을 줄인 배포

연수생 PC에 Docker·Python을 설치하지 않습니다. Stanza 서버는 Cloudflare Workers Builds에서 이미지를 만들고 Cloudflare에서 실행하며, 앱의 기본 `pnpm dev`는 비공개 원격 서비스 바인딩으로 연결합니다. 로컬 D1/R2는 그대로 사용합니다. 연구소 라이브러리의 구조 분석을 유지하면서 PC 설치 과정을 줄였습니다. 서버 내부의 컨테이너는 남아 있으며, 원격 빌드·실행 확인은 실제 Cloudflare 배포 때 진행합니다. [연수 환경 준비](TRAINING-SETUP.md).

Stanza는 Apache-2.0 라이브러리이며 모델은 해당 모델·학습 데이터의 별도 이용 조건도 확인해야 합니다. [Stanza 저장소·라이선스](https://github.com/stanfordnlp/stanza), [한국어 GSD 데이터](https://github.com/UniversalDependencies/UD_Korean-GSD).
