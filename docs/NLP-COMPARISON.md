# 한국어 분석 선택과 국내 연구기관 공개 도구 비교

조사·구성 변경일: 2026-10-25. 사용자 요청에 따라 Stanza 서버를 제거하고 기존 OpenRouter 문맥 분석 호출로 통합했습니다. UDPipe 2는 적용하지 않으며 학생 발화를 연구기관 서버로 보내지 않습니다. Kiwi도 사용하지 않습니다.

## 현재 분석

1. D1에 학생이 제출한 원문과 음성 인식 원문을 따로 보존합니다.
2. OpenRouter openai/gpt-4.1에 현재 원문·같은 활동 최근 발화 최대 4개·당시 평가 기준을 전송합니다. 이름·학년·반·번호는 별도 필드로 보내지 않습니다.
3. 모델이 구체성 4영역, 사용자 평가 기준, 반어·부정 범위, 핵심 표현을 한 호출에서 제안합니다.
4. 서버가 Zod 스키마·점수 범위·기준 ID·현재 원문에 존재하는 인용/표현을 검증합니다. 핵심 표현 중복은 제거하고 원문 등장 횟수를 직접 계산합니다.
5. 불명확한 반어와 이중 부정은 교사 확인 대상으로 표시합니다. 실패한 분석은 점수 0으로 꾸며 표시하지 않습니다.

현재 결과는 형태소·품사·기본형·의존 관계 분석이 아닙니다. 핵심 표현은 모델이 선택한 표면 표현이고 빈도는 문자 그대로의 등장 횟수입니다. 과거 Stanza 자료는 수정하지 않고 과거 방식임을 표시합니다. 변경 전후의 방법 차이는 학생 변화와 구별해야 합니다.

## 추천 판단

별도 연구용 형태소 분석을 도입한다면 국내 기관의 직접 공개 도구인 한나눔과 꼬꼬마를 실제 교과 발화·오탈자·띄어쓰기 오류에 대해 먼저 비교하는 것이 적절합니다. 반어 연구에는 중앙대 KoCoSa가 훨씬 직접적인 후보입니다. 다만 한나눔/꼬꼬마만으로 반어·이중 부정을 정확히 판별한다고 볼 수 없고, KoCoSa의 특정 데이터셋 성적을 초등학생 이미지 요청의 정확도로 옮길 수 없습니다.

현재 연수 앱에는 설치·운영 비용 제약에 맞춰 OpenRouter 한 호출을 유지합니다. 국내 오픈소스 분석기와 동일한 성능으로 확인됐다는 의미는 아닙니다. 향후 자체 분석을 적용한다면 연구기관 서버로 발화를 보내는 방식보다 라이브러리를 직접 실행하는 방식을 우선 검토합니다.

## 검증 범위

자동 시험은 원문에 없는 핵심어·인용 거부, 한 글자 내용어·중복·횟수 집계, 평가 기준 당시 버전, 교사 검토 표시를 확인합니다. 실제 OpenRouter 합성 예문 7개에서 단일 부정·완곡한 긍정·의무·포함절·문맥 없는 반어·문맥 있는 반어·관리 명령의 스키마와 기대 범위를 확인했습니다. 문맥 있는 반어도 판단 유보로 반환될 수 있습니다. 이는 작은 회귀 시험이며 정확도 측정이나 연구 라이브러리 간 성능 비교가 아닙니다.

문자 API는 provider.data_collection=deny로 제공자 수집 정책을 제한합니다. 이미지 API의 같은 옵션 지원 여부와 계정 설정은 [OpenRouter 공식 설명](https://openrouter.ai/blog/tutorials/image-generation-models/)을 따릅니다. 앱은 무보관·국내 처리까지 보장한다고 표시하지 않습니다.


현재 대시보드의 평균·추세에는 평가 기준과 분석 버전이 모두 같은 기록만 포함합니다. 이전 Stanza 방식의 개별 기록은 그대로 열람하되 새 방식의 평균에 섞지 않습니다.
