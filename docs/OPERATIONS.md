## 2026-11-05 1차 성능 재점검

기존 30명 저장 시험은 이미지 GET을 순차 확인했으므로 동시 재접속 성능을 입증하지 않았습니다. 이번에는 개별 합성 계정 20개로 실제 생성한 이미지에 대해 동시 조회·로그아웃·재로그인을 측정했습니다. 원본 20장과 기록은 저장됐지만 개선 전 20개 동시 전송은 모두 30초 기한을 넘겼습니다.

전체 자료의 5초 반복 조회를 변경 표식 조회로 바꿨습니다. 처리 중 5초·유휴 60초, 숨겨진 탭은 중지하며 변경 시에만 전체 자료를 받습니다. 응답 본문은 이 합성 자료에서 평균 약 8,492바이트에서 128바이트로 줄었습니다. 요청 빈도까지 합치면 유휴 상태의 반복 전송이 크게 줄어듭니다. 생성 대기·분석 완료·이미지 변경·일정·한도·배정 회수는 상태 시험으로 확인합니다.

512픽셀 미리보기는 합성 원본 20장 합계 4,948,108바이트를 1,091,005바이트로 줄였습니다(약 78%). 인증 후 ETag 재검증에서만 304를 반환합니다. 일반 Worker의 이미지 읽기 표본 129건은 outcome=ok, CPU p95 5ms·최대 10ms였습니다. 이는 본문 전송 완료 시간을 뜻하지 않으며 모든 실행의 Free 한도 준수를 보장하지 않습니다.

**운영 동시 재접속 성능은 아직 통과하지 못했습니다.** 보완 후 첫 미리보기 조회는 20/20 성공·p95 약 9.06초였으나 재로그인 후 강제 본문 재전송에서는 19건이 30초를 넘겼습니다. HTTP/2 별도 비교도 19/20만 기한 내 완료했습니다. 인증된 304는 20/20 성공했지만 HTTP 시험의 명시적 재검증이며 모든 학생 브라우저의 캐시 동작을 입증하지 않습니다. 대표 브라우저 1개에서는 재로그인 후 미리보기가 표시됐습니다.

같은 PC에서 R2·API를 거치지 않는 약 88KB 정적 파일도 동시 전송 시 14/20이 30초를 넘겼습니다. 일부 이미지 시험과 겹친 보조 비교이므로 정밀한 단독 대조군은 아니지만, R2 저장이나 앱 쿼리만을 원인으로 단정할 수 없습니다. 와이파이·PC 보안 소프트웨어·인터넷 회선·Cloudflare까지의 경로 중 어디가 원인인지 확정되지 않았습니다. 연수 장소의 개별 계정·실제 브라우저 동시 확인, 다른 회선과의 비교가 남아 있습니다. 과거 저장 성공 결과를 근거로 현장 속도를 보장하지 않습니다.

## 동시 접속과 지연

30명 동시 접속과 30장의 즉시 완성은 다릅니다. 운영 큐는 소비자 1개가 배치당 최대 6개 작업을 병렬 처리합니다. 배치 크기 1·소비자 최대 6 설정은 신규 큐가 처음에 한 개씩 처리하다가 약 2분 후에야 동시성을 늘리는 지연이 실제 배포에서 관찰되어 변경했습니다. 현재는 자동 확장을 기다리지 않고 배치 안에서 작업을 병렬 처리하며, 큐 호출 하나에서 모두 완료를 기다린 뒤 개별 메시지를 확인합니다. 모델 지연·OpenRouter 잔액과 속도 제한에 따라 대기할 수 있습니다. 학생별 생성 작업은 하나씩 수락합니다. 같은 요청 번호의 재전송은 기존 작업을 돌려줍니다. 업로드는 전체 4개 본문 처리 슬롯을 사용하며 나머지는 같은 업로드 번호로 다시 시도합니다. 응답 연결이 끊긴 경우에도 같은 번호로 이미 저장됐는지 재확인합니다.

## 무료 제공량과 앱 제한

- 배포 전체 하루 발화 수락 상한 300회(한국 시간). 30명 × 10회이며 수업이 여러 개면 합산됩니다. 실패·무시·수정도 수락됐으면 횟수를 사용합니다.
- 이미지·백업 저장 상한 8GB. 원본·수정본·미리보기·화면에서 제거한 원본·백업 사본을 모두 포함합니다. 저장 전 D1의 단일 조건문과 트리거로 원자적으로 예약하므로 동시 저장이 상한을 넘지 않습니다.
- 저장량은 합계 행에서 읽어 파일 개수에 비례하는 반복 스캔을 피합니다. 불확실한 R2 쓰기 실패는 예약량을 남겨 보수적으로 계산합니다. 과거 백업 manifest는 마이그레이션에서 임시 1MiB로 넣고, 새 파일 저장 전에 R2 실제 크기로 보정합니다.
- 80%부터 교사 백업 화면에 경고. 상한 도달 시 새 파일 저장만 중지하며 로그·원본 자동 삭제 없음. 실제 파일과 메타데이터가 확정되기 전 성공 표시 없음.
- 명단 300명은 25명씩, 비밀번호 재발급은 20명씩 나누어 처리합니다. 여러 학급/500명 개별 배정은 25행씩 묶은 SQL로 저장하며 D1의 요청당 쿼리·바인딩 한도를 고려합니다.
- 매분 Cron은 유지보수 작업 하나만 큐에 보냅니다. 유지보수도 발행 개수·업로드 복구·백업 만료 삭제량을 나누어 처리합니다. Free 큐 메시지 보관은 24시간이며 장기 대기 작업의 상태는 D1에 남아 다시 발행됩니다.
- R2 무료량은 계정 단위입니다. 앱의 8GB 제한은 전용 버킷의 용량 안전장치이며 계정의 다른 버킷·요청량·외부 수동 업로드 비용까지 제한하지는 않습니다. R2 활성화·결제수단 등록이 필요하고 초과량은 과금됩니다. OpenRouter 비용도 별도입니다.
