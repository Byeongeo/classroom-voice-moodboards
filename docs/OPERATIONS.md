# 30명 수업의 운영 판단

30명의 접속 자체보다는 이미지 생성 API의 처리 시간·계정 한도·잔액이 주요 병목입니다. 화면 배포, API, D1, 이미지 파일 저장을 분리하고 이미지·분석 작업을 큐로 넘겨 연결 끊김과 느린 모델 응답을 처리하도록 설계했습니다.

## 동시 사용

- 학생별로 한 생성 작업만 동시에 수락합니다. 중복 클릭·재전송은 같은 요청 ID로 처리합니다.
- 큐 소비자 최대 6개, 배치 크기 1입니다. 30명이 한 번에 요청하면 대기 후 순차 처리됩니다. 접속 30명과 이미지 30장의 즉시 동시 완성은 다릅니다.
- 예를 들어 한 작업이 60초 걸린다는 가정에서는 생성만으로 약 5회차가 필요합니다. 약 5분이라는 계산은 측정값이 아니며, 실제 계정의 속도·분석 작업·재시도에 따라 달라집니다.
- 429/일시 오류는 재시도하며 402/모델 오류 등은 실패 기록을 남깁니다. 응답이 유실된 외부 호출의 중복 과금 가능성까지 제거하지는 못합니다.
- 교사가 지정하는 활동·학생별 한도 외에, 배포 전체의 하루 요청 상한은 기본 900회입니다. 한국 날짜 기준이며 `MAX_CLASS_COMMANDS_PER_DAY`로 조정합니다. 실패·무시·직접 입력도 수락된 요청이면 횟수에 포함합니다.
- 원본 이미지 업로드는 발화와 분리해 활동당 50회, 4MB·4096픽셀로 제한합니다. 업로드 본문을 읽기 전에 D1에서 최대 4개의 처리 슬롯을 확보하고, 나머지는 브라우저가 같은 번호로 잠시 뒤 다시 시도하여 한꺼번에 큰 버퍼를 만들지 않도록 합니다. 업로드는 발화 한도를 사용하지 않습니다.

## 저장 보장 범위

| 상황 | 동작 |
| --- | --- |
| 새로고침·탭 닫기 | D1/R2에서 발화와 이미지를 다시 조회 |
| 브라우저 연결 끊김 | 이미 수락한 큐 작업은 서버에서 계속 처리 |
| 큐 발행 실패 | D1의 미발행 기록을 Cron이 재발행 |
| R2 업로드 실패 | 성공 표시하지 않고 재시도·실패 기록 |
| R2 업로드 후 D1 실패 | 같은 R2 키를 확인해 기존 이미지로 D1 연결 복구 |
| 다른 학생의 이미지 ID 추측 | 서버가 소유자를 검사하여 접근 거부 |
| 분석 실패 | 이미지·원문은 유지하며, 분석 실패 상태를 표시. 지표를 임의로 0으로 채우지 않음 |
| 활동 삭제 | 학생 활동 목록에서 숨김. 교사 분석·원문·이미지 보존 |
| 백업 기간 만료 | 백업 사본만 정리. 원본 학습 자료 유지 |
| 학생의 이미지 X 제거 | 화면에서 숨기고 작업 이력을 추가. 원본·수정본·발화·백업은 보존 |
| 업로드 중 연결 종료 | 저장한 R2 체크포인트로 D1 확정 복구, 파일이 없으면 실패 시도 기록 보존 |

완전한 무손실·무장애를 보장하지 않습니다. 장기 장애, 공급자 오류, 계정 정지·저장 한도, 외부 호출 응답 유실은 별도로 관찰해야 합니다. 큐 DLQ와 `events.status/error_code`, `analysis_status`, 백업 상태를 확인할 수 있습니다.

## 검증 결과와 범위

`pnpm test`는 30명의 동시 발화 수락과 D1 30개 원문·R2 30개 이미지 연결 및 다시 읽기를 검증합니다. 실제 로컬 D1/R2를 사용하되, API 핸들러는 Node 테스트 실행기에서 동작하고 OpenRouter 응답·큐 배달은 모의 처리합니다. 수업 인터넷 환경이나 운영 Cloudflare 전체의 부하 시험이 아닙니다.

실제 과금 API를 포함한 30명 테스트를 아직 수행하지 않았으므로 ‘운영 환경에서도 문제없음’으로 확정할 수 없습니다. 실제 키·계정의 제한을 확인한 뒤 먼저 소수 요청, 이후 30명으로 단계적으로 확인해야 합니다. 현재 설정은 처리 누락보다 대기와 복구를 우선합니다.

키 설정 후 소수 실제 요청으로 이미지 생성·참조 이미지 수정·원문 분석을 확인했습니다. 분석 완료까지 각각 약 23.1초와 20.4초가 걸렸고 D1/R2 기록을 다시 읽었습니다. 이 두 요청의 결과를 30명 동시 처리 시간으로 환산하지 않습니다. 원격 Stanza 서버의 빌드는 Cloudflare Workers Builds로 옮겨 연수생 PC의 Docker 설치를 제거했으며, 원격 빌드·연결은 실제 배포 후 확인해야 합니다.

## 데이터 양과 비용 계획

하루 30명 × 10회 = 최대 300건입니다. 이미지가 평균 1MB라는 가정에서는 약 300MB/수업, 20번 수업은 약 6GB입니다. 이는 용량 계획용 가정입니다. 실제로 확인한 JPEG 두 장은 약 125~135KB였으나 전체 수업의 평균 크기로 볼 수는 없습니다. 이미지 크기와 편집·백업 사본 개수에 따라 달라집니다. 이미지를 Base64로 D1에 넣지 않고 R2 파일로 저장합니다. 기본 요청은 JPEG 압축 출력을 사용합니다.

Workers·D1·R2·Queues·Container 비용 외에 OpenRouter 생성·의미 분석 비용이 발생합니다. Container는 10분 유휴 후 잠들도록 설정하며, 한 인스턴스를 공유하고 원문을 접근 로그로 출력하지 않습니다.

백업 메타데이터는 25행씩, 이미지는 10개씩 처리합니다. 다운로드 파일이 커지면 80MB 이하의 ZIP 단위로 나누어 내려받도록 구성했습니다. 백업의 비밀번호/세션 제외와 수집 기간 특성은 README를 참고하세요.

학생의 이미지·전체 기록 다운로드도 큰 경우 64MB 단위의 ZIP 선택 버튼으로 나눕니다. 이미지 생성본뿐 아니라 업로드 원본과 모든 이미지 작업 이력, 복수 반·학생 배정 정보, 글 종류도 백업 대상입니다.
