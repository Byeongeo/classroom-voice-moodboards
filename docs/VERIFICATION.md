자동 테스트의 API 핸들러는 Node에서 실행하며 저장소는 실제 로컬 workerd의 D1/R2를 사용합니다. AI 응답과 큐 배달은 모의 처리합니다. 여기서 얻은 지연 시간은 실제 이미지 생성 속도나 운영 Cloudflare의 30명 부하 성능을 뜻하지 않습니다. 원시 결과는 `output/test-results.json`, `output/load-results.json`에 있습니다.

실제 API 확인은 별도의 합성 학생 계정(5학년 2반 99번)으로 진행했습니다. 첫 제출은 실행 중인 서버가 이전 설정을 보유하여 `API_NOT_CONFIGURED`로 종료되었고 원문은 보존되었습니다. 서버 재시작 후 생성은 23.1초, 수정은 20.4초에 분석까지 완료되었으며 각각 한 번의 처리로 성공했습니다. JPEG 크기는 134,918바이트와 124,702바이트였습니다. 수채화 스타일, 파란 우산·고양이 유지, 빨간 튤립 3송이를 보라색 5송이로 수정한 결과를 시각적으로 확인했습니다. 수정본의 `parent_image_id`가 원본과 일치했고 동일 요청 번호 재전송도 같은 이벤트를 반환했습니다. 결과는 `output/live-check.json`과 `output/live-generate.jpg`, `output/live-edit.jpg`에 있습니다.

문맥 분석 결과는 `output/live-language-check.json`입니다. 문맥 없는 ‘참 잘했네’는 판단 유보, 꽃병을 깨뜨린 문맥에서는 반어 가능으로 반환했고, 완곡한 긍정·의무 표현은 이중 부정 및 교사 검토 대상으로 처리했습니다. 이는 작은 수작업 예시 집합을 확인한 결과이며 일반적인 정확도나 30명 동시 실 API 호출을 검증한 결과는 아닙니다.

확장 기능의 실제 API 결과는 `output/live-image-history-check.json`입니다. 업로드한 JPEG 원본을 다시 읽어 바이트가 동일함을 검사했고, 삭제·복원·참조 이미지 수정·보관 이력이 연결됨을 확인했습니다. 한글 포스터는 약 23.1초에 분석까지 완료됐으며 `output/live-korean-poster.jpg`를 시각적으로 검토했습니다. UI에서도 별도의 업로드와 X 제거를 확인했습니다. 전체 기록 ZIP에서 이미지 4장, 발화·업로드 5건, 이미지 작업 8건을 확인한 결과는 `output/browser-download-check.json`입니다. 그 뒤의 추가 검증 기록도 로컬 D1에 남습니다.

마이그레이션 전 로컬 D1은 `output/pre-participant-image-migration.sql`로 백업했습니다. 기존 활동이 있는 데이터의 외래 키와 반 배정을 유지하는 마이그레이션 검사도 통과했습니다. 이 SQL에는 로컬 인증 해시가 들어 있으므로 공개 저장소나 배부 자료에 포함하지 않습니다.

연수 기본 경로는 [Docker 설치 없는 준비 안내](TRAINING-SETUP.md)를 따릅니다. 현재 검토용 localhost는 미리 준비한 Python 직접 실행 서버를 연결한 개발자 경로입니다. 원격 Cloudflare Stanza 연결 자체는 아직 배포 전이므로 확인하지 않았습니다.

로컬 검토 주소: `http://127.0.0.1:8787`.

- 관리자 비밀번호: `<private-TEACHER_PASSWORD>`.
- 예시 학생: 5학년 / 2반 / 1번 / 이름 `예시학생` / 비밀번호 `sample-pass`.
- 위 계정과 활동은 로컬 D1에만 있습니다. 실제 학생 정보가 아니며 원격 배포에 복사하지 않습니다.
- 검토용 관리자 비밀번호를 운영 환경에 사용하지 않습니다. 실제 키는 채팅이나 소스에 넣지 않고 `.dev.vars` 또는 Cloudflare Secrets에 설정합니다.

활동별 배정 확장은 `0004_activity_participants.sql`로 적용했습니다. 로컬 적용 전 SQL 백업은 `output/pre-activity-participant-migration.sql`에 보관합니다. 기존 활동은 `class` 모드로 유지하며, 직접 배정한 활동은 학급·학생 설정을 별도로 저장합니다. 활동과 배정은 D1 배치로 함께 저장하고 잘못된 대상을 포함한 요청은 변경 전에 거부합니다. 새 배정 테이블 두 개도 백업에 포함되는 것을 확인했습니다.
